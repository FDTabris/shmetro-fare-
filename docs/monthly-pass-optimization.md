# 月卡/次卡优化折线图设计方案

## 背景

当前消费额折线图中，方案一和方案二两条折线都是按“纯单程票累计支出”进行计算的。也就是说，它们只考虑了自然月内按单程票累计消费的金额，没有把“在同一自然月里，买一次或多次 45/60/90 次卡，覆盖部分或全部乘车次数，并以此降低总支出”纳入计算。

这会导致图表在用户关心“一个自然月内更省钱”的场景下，出现明显偏差：

- 方案一、方案二的折线过高，无法体现“如果使用次卡，可能比单程票更划算”的真实总消费。
- 用户无法直观看到：在某个乘车次数区间内，方案一 or 方案二是否应该买次卡。 
- 当前的原方案“现行方案”仍然保持不变，但新方案一/二缺少“最优月卡策略”版本。

## 目标

1. 为图表增加一个“是否使用次卡优化”的切换按钮，并且与“不优化原始新方案折线”的状态形成反向联动。
2. 当“启用次卡优化”时，方案一/方案二的折线替换为“按月内最优次卡策略计算后的总消费额”；同时关闭原始未优化的方案一/方案二折线。
3. 当“关闭次卡优化”时，方案一/方案二恢复为原始单程票累计支出折线；同时关闭优化后的新折线。
4. 原方案“现行方案”始终不参与次卡优化，保持原有折线逻辑。
5. 文档重点放在“在一个自然月里，如何选择次卡组合，才能让总开支最低”，而不是泛泛地讨论是否适合买卡。

## 设计原则

### 1. 只优化新方案

只有以下两条新方案允许结合次卡优化：

- 方案一
- 方案二

现行方案保持原样，不参与任何月卡优化，以免出现“用户以为原方案也能买次卡”的误导。

### 2. 开关语义清晰

UI 中提供一个单一切换按钮，如：

- “启用次卡优化” / “关闭次卡优化”

其含义为：

- 开：在自然月内，按照该方案的最优次卡策略来计算累计总支出，并且不再绘制原始未优化的新方案折线。
- 关：按纯单程票累计支出来算，并重新绘制原始未优化的新方案折线，不显示优化折线。

该按钮不是“额外叠加一条线”，而是“按状态互斥地切换两套折线”：

- 启用优化时：只显示优化版折线，隐藏原始新方案折线。
- 关闭优化时：只显示原始新方案折线，隐藏优化版折线。

### 3. 折线只展示“最优总支出”

对于同一个方案，固定乘车次数 N，在开启优化后，图表上应该显示：

- 仅展示最佳次卡策略对应的总消费
- 不展示原始未优化版本

也就是：

```
optimized_cost = min(
  no_pass_cost,
  best_pass_cost
)
```

其中 `best_pass_cost` 是在一个自然月中，按最优次卡策略覆盖 N 次出行时的总价。

与其余不需要考虑的组合相比，只有 0 / 45 / 60 / 90 次卡的状态需要被评估。因为 45 次卡在三种套餐中价格最低，但超出 90 次卡价格一半的组合并无实际意义，且更高组合也完全超出当前图表与需求的范围。

## 业务定义：什么叫“月卡最优”

在一个自然月内，用户可能需要乘坐 N 次地铁。对于某个固定的票价方案 S，存在以下两种支出模式：

1. 不买次卡：按单程票累计支出计算。
2. 买次卡：使用 45 次卡 / 60 次卡 / 90 次卡中最优组合覆盖部分或全部乘车次数，剩余次数按单程票支付。

如果某一种次卡策略能让总支出更低，则它应被视为该月更优策略。

因此，优化后的累计消费额可以定义为：

```
monthly_optimal_cost(S, N) = min(
  single_ticket_total(S, N),
  min_{pass_state in {0,45,60,90}} total_cost(pass_state, S, N)
)
```

其中：

- `single_ticket_total(S, N)`：按该方案计算的纯单程票累计支出，包含自然月累计折扣的影响。
- `pass_state`：仅考虑四种状态：不买次卡、买 45 次卡、买 60 次卡、买 90 次卡。
- `total_cost(pass_state, S, N)`：在该状态下覆盖 N 次乘车后的总价。

注意：由于 45 次卡超过 90 次卡价格的一半，所以买多次 45 次卡没有实际意义；同理，多张 60 次卡或更高容量的组合也完全在当前需求范围之外，不应被纳入候选策略。

## 次卡套餐规则

目前项目中已定义的套餐：

- 45 次卡：¥210
- 60 次卡：¥270
- 90 次卡：¥390

这些套餐的使用前提：

- 仅用于方案一和方案二参与比较；
- 不与现行方案共存；
- 只在“启用次卡优化”状态下生效；
- 仅考虑 0 / 45 / 60 / 90 次卡的四种状态，不考虑超过 90 次的月内候选覆盖范围。

更进一步地说：

- 45 次卡超过 90 次卡价格的一半，因此买多个 45 次卡没有价值；
- 更高容量的组合也不需要纳入最终候选，因为图表只展示 90 次以内的自然月累计支出；
- 任何“超过 90 次”的覆盖策略都不属于当前设计范围。

## 数据模型设计

建议增加一个“优化态”字段，放在图表数据构造阶段：

```js
{
  schemeKey: "scheme1",
  schemeName: "方案一",
  rides: 42,
  rawTotal: 180.12,
  optimizedTotal: 175.50,
  usePass: true,
  selectedPasses: [
    { rides: 45, price: 210 }
  ],
  strategyLabel: "买 45 次卡，超出部分按单程票"
}
```

其中关键字段包括：

- `rawTotal`：未优化的累计单程票支出
- `optimizedTotal`：启用次卡后，月内最优总消费
- `usePass`：是否启用次卡优化
- `selectedPasses`：本月实际采用的次卡组合
- `strategyLabel`：用户界面显示的推荐说明

## 计算算法

### 1. 先计算原始累计消费

对每个方案 S 和每个乘车次数 N，先算纯单程票的自然月累计支出：

```js
const rawTotal = getCumulativeSingleTicketSpend(distanceKm, schemeKey, rides);
```

这一步保持不变，确保当前图表的基础数据仍然成立。

### 2. 构造次卡候选策略

由于图表只展示自然月内最多 90 次的累计支出，并且 45 次卡超过 90 次卡价格的一半，所以买多次 45 次卡没有意义，其他更大容量的组合同样超出当前需求范围。最终只需要评估以下四种状态：

- 0 次卡：不买
- 45 次卡：只买 1 张
- 60 次卡：只买 1 张
- 90 次卡：只买 1 张

这四种状态足以覆盖我们需要考虑的“最省钱”选择，因为：

- 任何组合都不可能比单张更合适的次卡更划算；
- 图表不展示超过 90 次的区间；
- 组合成本会明显偏高，不属于需要纳入最优决策的候选。

### 3. 使用简单比较求最优状态

对于每个 `rides` 次数，只需要比较：

- 不买次卡：`single_ticket_total(S, rides)`
- 买 45 次卡：`210 + remaining_single_ticket_cost`
- 买 60 次卡：`270 + remaining_single_ticket_cost`
- 买 90 次卡：`390 + remaining_single_ticket_cost`

其中 `remaining_single_ticket_cost` 表示超过次卡覆盖次数后，剩余出行按照该方案的单程票价格继续累计。

简化公式为：

```js
const passOptions = [
  { rides: 45, price: 210 },
  { rides: 60, price: 270 },
  { rides: 90, price: 390 },
];

const bestPassCost = passOptions.reduce((best, pass) => {
  const covered = Math.min(rides, pass.rides);
  const remaining = Math.max(0, rides - covered);
  const total = pass.price + getSingleTicketCostForRemaining(distanceKm, schemeKey, remaining);
  return Math.min(best, total);
}, getSingleTicketCostForRemaining(distanceKm, schemeKey, rides));
```

最终取：

```js
optimized_cost = Math.min(single_ticket_total, bestPassCost);
```

### 4. 只替换方案一和方案二的折线

实现层面，最简单的方式是在图表生成数据时把 `schemeEntries` 改成：

```js
const schemeEntries = Object.entries(fareSchemes).map(([key, scheme]) => {
  const shouldOptimizePass = key !== "current" && passOptimizationEnabled;
  return {
    key,
    name: shouldOptimizePass ? `${scheme.name}（次卡优化）` : scheme.name,
    color: ...,
    data: rideCounts.map((rides) => ({
      rides,
      total: shouldOptimizePass
        ? getOptimizedMonthlyTotal(distanceKm, key, rides)
        : getCumulativeSingleTicketSpend(distanceKm, key, rides),
    })),
  };
});
```

其中：

- `current` 不受影响；
- `scheme1` / `scheme2` 在开启时被替换为“最优总支出”折线；
- 若关闭，则回到旧逻辑。

## 交互设计

### 切换按钮放置位置

建议放在图表头部附近，位于 `h2` 后方或图表上方：

- 标题：自然月单程票累计支出
- 按钮：启用次卡优化

示例：

```html
<section id="chartPanel" class="chart-panel hidden">
  <div class="chart-toolbar">
    <h2>自然月累计支出</h2>
    <button id="passOptimizationToggle" type="button" aria-pressed="false">
      关闭次卡优化
    </button>
  </div>
  <svg id="fareChart" ...></svg>
</section>
```

### 切换状态说明

按下按钮后：

- 切换为 `aria-pressed="true"`
- 显示文本更新为 `已启用次卡优化`
- 方案一/方案二的原始折线被隐藏
- 方案一/方案二的优化版折线被显示
- 迷你说明文本可显示：
  - “次卡仅对方案一、方案二生效；现行方案不参与优化”

按下按钮关闭时：

- 恢复原始方案一/方案二折线
- 隐藏优化折线
- `aria-pressed` 变回 `false`

### 用户看到的效果

在开启状态下，图中只显示“方案一（次卡优化）”和“方案二（次卡优化）”，而不再显示原始方案一/方案二的单程票折线。

这有两个好处：

1. 用户明确知道当前看到的是最优次卡方案。
2. 原始方案折线会在关闭时自然恢复，从而保持两套状态互斥且容易理解。

## 说明与可视化选项

### 1. 图例说明

曲线图的图例可以写成：

- 现行方案
- 方案一（原始）
- 方案一（次卡优化）
- 方案二（原始）
- 方案二（次卡优化）

如果 UI 开关关闭，则只显示原始版本；如果开启，则只显示优化版本。

这两套折线互斥显示，避免图表拥挤且避免用户混淆“哪个才是当前方案的真实状态”。

### 2. Tooltip 提示

鼠标悬停在任何点上时，可以显示：

- 方案名
- 乘车次数
- 累计支出
- 最优策略说明（如：买 90 次卡，节省 ¥XX）

示例：

```
方案一（次卡优化）
次数：68
累计支出：¥563.20
最优策略：买 60 次卡 + 余票按单程票
```

这样用户能直接理解为什么折线会低于单程票版。

## 关键决策

### 决策一：优化只发生在新方案

这是最关键的要求，也是当前设计的底线。

- 现行方案：不支持次卡优化
- 方案一：启用时优化
- 方案二：启用时优化

这样可以保持“政策对比”逻辑清晰，并且避免“误把次卡优化当作原方案的一部分”。

### 决策二：折线的替换语义

“用新的折线替换两条新方案的折线”意味着在切换开启时，图表里实际展示的是新折线，而不是在原折线上叠加一个额外的优化路径。也就是说：

- 新方案折线在开启时被重写为优化版；
- 关闭时，把它恢复为原始累计单程票折线。

### 决策三：关注“最大程度节约开支”

设计的重点并不是判断“某个乘车次数是否值得买次卡”，而是：

- 在每个乘车次数点上，找出让总成本最低的次卡组合；
- 让图线真实反映用户在该月中“最省钱”的决策路径；
- 让用户看图时，能直观看到“买哪张卡更划算”。

## 可接受性标准

1. 用户可以切换“次卡优化”开关。
2. 开关打开时，方案一和方案二的原始折线被隐藏，优化版折线被显示。
3. 开关关闭时，方案一和方案二恢复为原始单程票累计支出折线，优化版折线被隐藏。
4. 现行方案仍然使用原始累计单程票折线。
5. 候选策略仅考虑 0 / 45 / 60 / 90 次卡，且不考虑超过 90 次的月份覆盖范围。
6. 视觉说明明确：优化后的曲线表示“在该月内使用最优次卡策略后的总支出”。
7. 线条上下文和 tooltip 能清楚说明“哪种次卡策略更省钱”。

## 实施建议

推荐实现顺序：

1. 新增切换按钮与状态管理。
2. 抽离一个 `getOptimizedMonthlyTotal(distanceKm, schemeKey, rides)` 函数。
3. 让方案一/方案二在开关开启时走优化逻辑。
4. 让现行方案永远走原始逻辑。
5. 更新 tooltip/图例文案，突出“次卡优化”的语义。

这样可以把改动集中在图表计算层，不影响路径查询、地铁网络绘制与票价展示。

## 结论

这个需求的核心，不是简单地在图表上“画一条更低的折线”，而是把用户在自然月中的“最优消费决策”观测化。也就是说：

- 方案一和方案二的折线应当代表“如果按最优次卡策略花钱，月内会怎么花”；
- 现行方案则保留“纯单程票”的真实成本；
- 用户可以通过一个开关，切换看“最优消费”还是“原始累计单程票”，从而做出更准确的方案比较。

这能让图表不仅反映价差，还能反映“在同一自然月里如何用次卡最大程度节约开支”。
